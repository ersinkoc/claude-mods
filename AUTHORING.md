# KOZMOS — authoring guide

Every KOZMOS mod is a Claude Code **function-hooks plugin** written from
scratch for this bundle. No code is copied from other mod collections.
`mods/bridge/` is the reference implementation: read it before writing a mod.

The API declaration is `types/claude-code.d.ts` (≈21k lines). Grep it for
the name you need (`'tool.call'`, `Spinner: {`, `export type RasterProps`)
and read the declaration it lands on. It is the authority.

## Layout of one mod

```
mods/<name>/
  .claude-plugin/plugin.json   { name, version "0.1.0", description, author {name:"KOZMOS"}, types?, userConfig? }
  hooks/hooks.json             { "description": "...", "modules": ["./register.tsx"] }
  hooks/register.tsx           export const register: Register = (on, options) => { ... }
  hooks/<scene>.tsx            optional Client surface modules (terminal animation)
  hooks/lib/kz.ts, probe.ts    GENERATED by `node scripts/sync-shared.mjs` — never edit in a mod
  types/index.d.ts             $.state contract (when the mod keeps $.state values)
  tests/register.test.tsx      at least one test, run by `claude plugin test mods/<name>`
  README.md                    short, English then Turkish ("## Türkçe")
```

`plugin.json` with state names `"types": "./types/index.d.ts"`. The contract:

```ts
export type FooSnap = { ... }
declare module 'claude-code' {
  interface PluginState { '<name>': { snap: FooSnap | null; isHidden: boolean } }
}
```

## Hard rules the engine enforces (learned the hard way)

1. **`$` never leaves the file.** `$` may be passed only to functions
   *declared at the top level of the same file* (a `function` declaration
   or a top-level `const f = (...) =>`). Not to closures defined inside
   `register`, and **never across an import**. So helpers that need `$`
   (sampling, toggling a pane, running git) are top-level functions in
   `register.tsx`; `lib/kz.ts` and `lib/probe.ts` are pure (no `$`).
2. **No `import()`**. Plain `import` declarations only, of files inside the plugin.
   Imports of plugin files use the `.ts`/`.tsx` suffix: `from './lib/kz.ts'`.
3. **Render hooks never write state.** Read with `read($, atom)` while drawing;
   write with `update($, atom, fn)` from other hooks, timers or Button handlers.
4. **State refs are literals:** `atom({ plugin: '<name>', key: 'snap' } as const, initial)`
   with `plugin` equal to the manifest name and each key declared in the contract.
5. **Observer hooks on gating events get a `.catch`** so they never block:
   `on('tool.call', hook).catch(($, e, next) => next(e))`.
   Same for `prompt.submit` and `command.run` hooks that are not your own command.
6. **Streaming events** (`turn.step`, `process.spawn`) take an async generator:
   `on('turn.step', async function* ($, e, next) { const r = yield* next(e); ...; return r })`.
7. **The desktop wraps sibling elements onto new lines.** On `desktop`
   draw a row (or a whole card) as **one `Svg`**, with CSS animation inside
   it (`<style>` in the SVG: keyframes run in the compositor, no redraws).
   Use `svg()`, `svgText()`, `svgBar()`, `SVG_BASE_CSS` classes (`t s m k p`)
   from `lib/kz.ts`, so light and dark themes both work.
8. **Terminal has no `Svg`.** Use `Text`/`Box` with colors, a `Raster`
   (colored cell grid; `Canvas` in `lib/kz.ts` packs it) for pictures, or a
   `Client` surface module for real animation (see below).
9. Branch on the surface: `const ui = $.ui.resolve(e); if ('Svg' in ui && e.surface !== 'terminal') { ... }`.
   `vscode` and `mobile` also have `Svg`; `mobile` has no `Input`/`Select`/`Client`.
10. **Width:** a `Pane` or `AbovePrompt` hook sizes to `e.props.bodyColumns`
    (cells). Desktop pixels: `pxOf(e.props.bodyColumns)` from `lib/kz.ts`.
11. A Button's `onPress` is a closure; it may call `update($, atom, fn)` and
    top-level functions with `$` (the validator allows `$` captured in a
    handler written inline in the render hook).
12. `ui.render` for `AbovePrompt`: **compose, don't replace.** Other mods
    draw there too. Do `const drawn = await next(e)` and return
    `<Box flexDirection="column">{drawn}{mine}</Box>`, or just `drawn` when
    you have nothing to show. Respect `e.props.hasSurvey` (show nothing
    extra) and keep the band small: 1–4 rows, `e.props.maxRows` is the cap
    for the whole band. Every band mod has a hide toggle (Button `✕` with
    `role="dismiss"`, plus a `/<name>` command) persisted in `$.store`.
13. Panes: `$.ui.open({ id, title })` / `$.ui.close({ id })` / `$.ui.panes()`.
    A pane opened unasked seats only from 144 terminal columns; open it from
    the mod's command. Only `bridge` auto-opens by default; any other pane
    may offer `autoOpen` in `userConfig` defaulting to **false**.
14. A command: `await $.command.register({ name, description, immediate: true })`
    in `session.start`, answered by
    `on('command.run', { command: '<name>' }, async $ => ({ text: '...' }))`.
    Command names are the mod name (and sub-arguments via `e.args`).
15. Timers: `$.clock.every(ms, () => void work($).catch(() => undefined))`
    started in `session.start`. Keep the interval ≥ 500 ms for data work;
    publish to `$.state` only when the value changed (compare JSON), so idle
    panes do not redraw.
16. Shelling out: write a top-level `sh($, argv, timeoutMs, cwd?)` that wraps
    `$.process.run` in try/catch and returns stdout or `undefined`, then feed
    the text to a `lib/probe.ts` parser (see `mods/bridge/hooks/register.tsx`,
    `readGit`/`readSys`). Never shell out from a render hook.
17. Persisting across sessions: `$.store.get(key)` / `$.store.set(key, value)`
    (per plugin). Keep values small JSON.
18. Everything must also make sense with **no data yet** (fresh session, not
    a git repo, no subscription → `rateLimits` empty, no GPU).

## Where the data comes from

| Need | Source |
| --- | --- |
| context fill, rate limits (`five_hour`, `seven_day`, resetsAt), session cost | `await $.session.usage()` → `{ startedAt, context: { tokens, window, percent }, rateLimits: [{ kind, percentUsed, resetsAt }], cost?: { usd } }`; or hook `session.measure` (fires when they move) |
| context breakdown by category | `$.session.usage({ breakdown: 'summary', columns })` → `context.breakdown` |
| model, effort | `await $.session.model()`; `turn.step` input has `model`, `effort`, `agentId` |
| each model request's tokens | `turn.step` generator result `.usage` (`input_tokens`, `output_tokens`, `cache_read_input_tokens`, `cache_creation_input_tokens`, `model`) |
| turn start / end | `turn.start` (`text`, `turnId`), `turn.complete` (`durationMs`, `reason`, `agentId?`, `usage?`) — `agentId` undefined means the main loop |
| every tool call, its input, result, duration | `on('tool.call', ...)`: `e.tool`, `e.tool_use_id`, `e.agentId`, the tool's input fields on `e`; `await next(e)` → `{ result, isError?, deny? }` |
| subagents | `agent.spawn` (input `description`, `subagentType`, `model`, `background`; result `{ agentId, model }`), `await $.agent.list()` → `[{ id, description, type, status, parentId }]` (status `pending running waiting idle completed failed killed`) |
| tasks / todos | `tool.call` on `TodoWrite` (`e.todos[]` with `content status activeForm`), `TaskCreate` (`subject`, result `.result.task.id`), `TaskUpdate` (`taskId`, `status`, `subject`) |
| spinner state | `ui.render` `{ component: 'Spinner' }`: `e.props.mode` is `requesting responding thinking tool-input tool-use`; return `next(e)` |
| prompts | `prompt.submit` (`text`) |
| git | `GIT_STATUS`, `GIT_HEAD`, `gitLogArgv(n)`, `GIT_NUMSTAT` + parsers in `lib/probe.ts` |
| CPU / RAM / disk / GPU | `WIN_SYS`, `MAC_TOP`, `/proc/stat`, `NVIDIA_SMI` + parsers in `lib/probe.ts` |
| sound | `$.audio.play({ asset: 'sounds/x.wav' })` — a file of the mod; `$.audio.speak(text)` |
| toast / status line | `$.ui.toast(text)`, `$.ui.status(text | undefined)` |

Prices for estimating a subagent's spend: `costOf(model, usage)` in `lib/kz.ts`.

## Client surface modules (terminal animation)

A `Client` runs a module of the mod in the drawing surface at up to 60 fps
with its own state and timers, so animation costs no hook round trips:

```tsx
// in register.tsx's AbovePrompt hook (terminal):
const { Box, Client } = $.ui.resolve(e)
return <Box flexDirection="column">{drawn}<Client key="heartline" module="./scene.tsx" width={cols} height={3} props={{ ...plain JSON data }} /></Box>

// hooks/scene.tsx
import type { ClientModule } from 'claude-code'
type P = { width: number; level: number }
type S = { t: number }
const Scene: ClientModule<P, S> = (props, surface) => {
  if (surface.state === undefined) {
    surface.setState({ t: 0 })
    surface.every(33, () => surface.setState({ t: (surface.state?.t ?? 0) + 1 }))
  }
  const { Box, Text } = surface.elements      // Box Text Button Input Select Link Code Markdown (no Raster, no Svg)
  return <Text color="#a78bfa">...</Text>
}
export default Scene
```

`props` is plain JSON (≤100k chars) and reaches the running instance on each
redraw with its state kept. `module` is a string literal path relative to
the file. Desktop draws `Client` too, but prefer one animated `Svg` there.

## Tests

`claude plugin test mods/<name>` runs `tests/*.test.ts(x)`. Nothing answers
beneath the mod: every `$` call your hooks make must be answered by an
`on('<event>', () => ({ value: ... }))` in the test, or be inside try/catch.
`mock.clock(on)`, `mock.env(on, {...})`, `mock.store(on, {...})` answer
those nouns. Mount a drawing with `$.ui.mount({ plugin, surface, component, requestId?, props })`
and check it with `find({ type: 'Text', text: /re/ })` / `find({ type: 'Svg' })`.
Loop the surface over `['terminal', 'desktop']`. Template:
`mods/bridge/tests/register.test.tsx`.

## The loop for each mod

```
node scripts/sync-shared.mjs                     # lays lib/kz.ts, lib/probe.ts
npx tsc -p tsconfig.json 2>&1 | grep "mods/<name>/"   # type errors of this mod only
claude plugin validate mods/<name>               # must end ✔ Validation passed
claude plugin test mods/<name>                   # must pass
```

Do not edit `shared/`, `types/`, `scripts/`, the root files, or another
mod's folder. A helper only your mod needs lives in `mods/<name>/hooks/`.
